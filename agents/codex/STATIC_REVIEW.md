# Dormant delivery review

This document describes **static verification**, not executed agent testing. No
success, convergence, runtime speed, numerical correctness, GPU operation, or
end-to-end compatibility result is claimed. The checkpoint, optimizer, inference,
and environment code paths have not been run for this contestant.

## Verification performed

- Source inspection of the actual shared `MazeEnv`, generation presets, block
  movement, traps/rewards, move budget, observation fields, agent interface, run
  store, and dashboard value-data contract. No maze was generated by that inspection.
- Primary-paper and official-documentation research recorded in `RESEARCH.md`.
- `ruff check agents/codex`: passed after import-order corrections.
- `ruff format --check agents/codex`: formatting checked.
- `python agents/codex/static_check.py`: parsed and compiled 14 Python files
  without executing their code objects; checked 55 guarded methods/functions,
  relative module/symbol references, configuration keys, module-level literal
  initialization, hidden-game attribute/import exclusions, and literal `READY = False`.
- Static JSON/TOML parsing and package-file review. CLI flags/config documentation
  checked against source. The nested package declares its own dependencies and
  entry point; shared package configuration is unchanged.
- Manual tensor-shape review: inputs `[batch,13,15,15]`,
  `[batch,13,21,21]`, `[batch,20]`; actor logits `[batch,4]`, values `[batch,2]`,
  hidden `[batch,128]`. Sequence inputs prepend time. Burn-in padding is excluded
  from hidden-state updates; training chunks are complete rather than padded.
- Manual review of dual GAE, zero terminal bootstrap, continued-episode rollout
  bootstrap, pre-observation hidden snapshots, same-mask policy ratios, clipping,
  detached burn-in, normalized advantages, finite-loss/gradient checks, and schedules.
- Manual training/inference feature-parity review: same memory writes, visits,
  recency, previous score delta/action, wall mask, scalars, and network inputs.
- Manual checkpoint review: versioned tensor/primitive payload, strict weights,
  weights-only load, optimizer/RNG/curriculum/actor histories, public-API trajectory
  reconstruction, log offsets, recorder rollback, atomic writes, coherent-update
  shutdown, and preservation of the previous checkpoint on mid-update errors.
- Manual activation review: the CLI checks before importing operational modules;
  constructors, forwards, action selection, training, evaluation, resume, writes,
  checkpoint reads, and direct adapter hooks check again. Status/help and static
  source inspection are non-operational. No import creates an instance/session,
  opens an output DB, initializes weights, or runs an episode. No guard override
  flag, environment variable, daemon, scheduler, or downloaded model is present.
- File-scope review: the contestant implementation is confined to `agents/codex/`.
  Shared rules, generator, observations, scoring, and Redbull remain
  unmodified. The Mac UI follow-up only adjusts the initial window size to fit a laptop display. The portability follow-up below adds setup files outside this directory.

The local dependency metadata reported PyTorch 2.14.0+cpu, NumPy 2.4.4, and Ruff
0.16.2. Reading that metadata did not import or run the learning implementation.
No extra ML package was installed for verification. Declared compatibility ranges
are not evidence of runtime testing across those versions.

## Corrections made during static review

Recurrent inference state is reallocated on reset so an inference-mode tensor is
not mutated outside inference mode. PPO metrics distinguish considered minibatches
from actual optimizer steps. Evaluation recordings mark errors honestly. Recurrent
sampling preserves contiguous histories; bootstrap does not consume actor state.
Recorded training rewards remain raw game deltas, separate from training objectives.
Pooling was vectorized to avoid hundreds of Python reductions per agent step.
Resume trims post-checkpoint telemetry and replaces active episode snapshots,
avoiding duplicate metrics after recovery. Resume log offsets are validated before
any log truncation. All of these are source-reviewed corrections, not demonstrated
runtime fixes.

## Limits and future authorized checks

Static checks cannot prove a numerical learning implementation correct, establish
training stability, ensure every hardware/backend path works, or show a competitive
policy. After activation is authorized, an operator should first use a small
explicit training budget, inspect metrics, verify checkpoint resume, and evaluate
only validation/held-out development cases before committing a long job. The README
contains all commands and recovery steps. Those operations are deliberately left
unexecuted, not left unimplemented.

Source auditing is not an adversarial sandbox proof. Running arbitrary Python in
the same process as the game permits general Python access; the policy's own code
uses permitted observations only. Use the JSON-lines adapter and an isolated
championship harness when process-level contestant isolation is required.

At handoff, `activation.py` remains `READY = False`.

## Apple Silicon portability follow-up

The macOS migration adds a guarded explicit MPS device choice, CPU-based action
sampling that works without an MPS torch.Generator, MPS RNG checkpoint storage,
and a Mac preset. CPU remains the default and auto still selects CUDA or CPU.
These additions were checked as source only, with no model initialization or
agent execution. The 55-guard count above includes the two new helpers.

The repository also has a separate setup/launch helper and Finder scripts, a
macOS guide, and a Pygame minimum version with universal2 wheels. Seven portability tests passed on Linux; five mock launcher orchestration and
two check window-size arithmetic using a fake display. They do not create game
environments, windows, or agent instances.
Those helper tests do not establish native macOS UI or MPS functionality.
